# Consensus methods used in the project

The repository contains several related but non-identical consensus formulations. Treat them as separate experimental methods.

## 1. Consensus on absolute power

State: active power `P_i`.

Generic discrete update:

```text
P_i(k+1) = P_i(k)
           + eps * sum_j a_ij [P_j(k) - P_i(k)]
           - leader_term_i
```

The leader term is driven by the overvoltage error. Clamp the state to the physically available power range.

Use when the research question concerns equalization in absolute kW.

## 2. Proportional consensus

State:

```text
rho_i = P_applied_i / P_available_i
```

with `0 <= rho_i <= 1` and:

```text
P_applied_i = rho_i * P_available_i
```

The leader receives the voltage-error correction; neighbours mix `rho`. This is appropriate when PV/BESS units are heterogeneous and the research question is relative participation rather than equal kW.

## 3. Olfati-Saber variant used in the project

One project implementation uses:

```text
X_i(k+1) = X_i(k)
 + (eps / weight_i) * sum_j a_ij [X_j/cap_j - X_i/cap_i]
 - beta_i * (E - E_ref)
```

with operational clipping.

Other legacy code uses an unnormalized state difference. Never mix both equations inside one comparison without naming the variant. Record:

- state units;
- `cap_i` definition;
- beta vector;
- leader index;
- epsilon rule;
- limits.

## 4. CORA / iCORA

CORA adds saturation-residual redistribution.

Conceptual flow:

1. carry residual `delta_M` from agents that hit limits;
2. distribute residual through the communication graph;
3. add distributed residual to the current state;
4. apply consensus + leader voltage correction;
5. clip each agent to min/max;
6. store the new residual generated by clipping.

This is especially useful with heterogeneous agent limits because a saturated unit's unmet contribution can be redistributed instead of silently lost.

## 5. Current PV+BESS leader-follower export-target consensus

The current BESS prototype is not the same as the utilization-factor leader-follower formulation in Kitso et al. (2025).

Current prototype logic:

```text
export_target_new = export_target - eps * L * export_target
leader_correction = gain * max(Vmax - Vlimit, 0)
export_target_new[leader] -= leader_correction
clip(0, PV_available)
```

Then:

```text
required_reduction = PV_available - export_target
BESS_charge = min(required_reduction, P_BESS_max, energy_room/dt/eta)
PV_curtailment = required_reduction - BESS_charge
```

SOC/energy is a **physical limiter**, not a consensus weight, unless an experiment explicitly changes that rule.

## 6. Literature leader-follower utilization factor (Kitso et al., 2025)

This is a separate benchmark concept:

- leader is associated with a bus violating a voltage limit;
- each BESS has utilization factor `U_i`;
- `P_ref,i = P_nom,i * U_i`;
- follower utilization factors track through neighbour communication;
- SOC is locally constrained; an unavailable BESS is excluded and neighbours compensate.

The paper also proposes a leaderless control with a shared utilization factor and an additional SOC-balancing rule. Do not label the current project controller as equivalent without explicitly adapting it.

## 7. Communication graph

Existing utilities support complete, ring, or edited/irregular undirected graphs.

Always record:

- adjacency matrix `A`;
- degree matrix `D`;
- Laplacian `L = D - A`;
- leader/pinning vector when applicable;
- epsilon calculation rule.

The project has used more than one epsilon rule historically. Preserve the rule belonging to the chosen method. Do not change epsilon merely to make methods converge faster without documenting it.

## 8. Controller stopping rules

Electrical stopping should be primary:

- `Vmax <= Vref + tolerance` for overvoltage mitigation;
- or infeasible because all control degrees of freedom are saturated;
- or iteration cap reached.

Consensus-state agreement alone is not sufficient if voltage remains outside limits.
